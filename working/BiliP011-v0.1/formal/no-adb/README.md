握手候选启动时拒绝已存在的4D00，等待本轮新出现的下载接口；不固定COM号。若有多个4D00、4064与4D00并存、接口身份/状态变化或配置错误，停止。**1782:4064的DIAG、AT、LOG等接口永不打开，绝不向它们发送BSL数据。** 打开后和发送前重新核对接口及活句柄；失去句柄后重新枚举、打开，并在新会话重新验证AutoD，旧会话版本不能授权新句柄CONNECT。

本轮完整尝试预算只有以下三项，计数发生在写API之前，失败或短写也消耗预算：

- MODE最多1次：`7E 00 00 00 00 08 00 FE 82 7E`。这是主动启动模式选择，可能改变启动状态、重启或使屏幕保持黑屏，不是被动读取。若已经被动收到有效AutoD版本，可跳过MODE。
- SYNC最多4次：单字节`7E`，间隔至少400ms；仅MODE写API已返回且等待版本、无待读输入/半包时允许。
- CONNECT最多1次：`7E 00 00 00 00 00 00 7E`。只由同一活会话完整、CRC16正确、精确`SPRD4:AutoD\0`版本授权，超时不重发；验证空ACK后停止。

初次被动接收100ms，已有分片只补读最多500ms；MODE后接收1.8秒，版本与ACK阶段各最多4秒，句柄丢失后的重开等待最多30秒。异常、未知回应、坏CRC、杂质、半包无法闭合或预算耗尽均保存原始字节并停；不会转入更宽松协议或执行自动修复。

**此候选全过程不调用ADB，不上传外部loader/FDL，不发送EXEC_DATA、内存、分区读写、擦除、解锁、reset或固件升级命令。** 关闭电脑串口句柄只表示HOST资源处理，不代表学习笔恢复。MODE/CONNECT可能改变临时启动会话，设备内部是否记录事件也不受HOST控制，不能把“无分区写命令”写成“完全被动”。
