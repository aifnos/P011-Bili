# P011 B站下载模式刷写包

入口：**设置 → 用户反馈**。名称、图标和列表位置保留，原反馈页内容替换为 B站。

**当前为待 system 实机验收的刷写候选包。** 完整 system 镜像已通过电脑端文件系统检查和全部原文件比对；下载模式已有 sysdumpdb 原件写回实测。这个包本身尚未在 P011 上完成 system 写入、正常启动、B站入口、播放、退出与恢复验收，也未在干净电脑验证首次驱动安装。

## 使用

1. 完整解压到本地可写文件夹，保留整个目录，电脑至少留出 6 GiB 空间。支持 Windows x64，自带 Python，不需要安装 Python 或启用 ADB。
2. 电脑须已有设备厂商提供的签名 SPRD 下载驱动。缺少驱动时程序停止；本包不捆绑未核实来源的驱动，也不修改驱动签名设置。
3. 先正常关机、拔下 USB，双击 **一键正式写入B站.cmd**。按提示准备，看到“等待接口已就绪”后才插入已关机的笔。
4. 程序核对唯一下载设备、GPT 和 uboot，读取完整 system 原件。仅当其 SHA-256 与支持底包完全一致时，才在电脑端重建候选、校验并完整写入。整个过程可能需要较长时间，以进度为准；保持供电及 USB 连接。
5. 写后完整回读，并核对关联分区。只有出现 `SYSTEM_IMAGE_WRITTEN_AND_FULL_READBACK_VERIFIED` 才表示写入与回读完成。随后拔 USB、正常开机，在“设置 → 用户反馈”检查实际功能。

支持底包：`z031_v2.4.0-20251128_174826-user`。除版本文字外还检查完整 system、uboot 与分区布局。其他版本、已修改过的系统或不同底包会保留读取结果并停止，不强行写入。

## 恢复和备份

**一键恢复原系统.cmd** 只从本文件夹的 `backups` 中选择属于当前设备的、校验通过的完整原 system，完整写回并全量回读。恢复绑定 USB 设备身份、原 GPT 和该设备 prodnv 指纹；请使用原电脑、原 USB 口并保留整个目录。它不恢复 userdata、NV、启动分区，不是整机救砖工具。

写入开始后发生异常，程序不重发、不自动擦除或回滚。保留日志和原备份，按恢复入口处理；设备无法进入下载接口时，恢复程序也无法完成恢复。system 修改镜像的实际接受与恢复路径仍待本包实机验收。

`backups` 中保存当前设备的原件，`logs` 中保存原始日志、协议记录、校验值和结果 ZIP。它们是私有诊断资料，不要发给其他用户。分发时使用未运行过的原始 ZIP；不要把用过的整个文件夹重新压缩分发。

## 包内内容

- `一键正式写入B站.cmd`：备份、重建完整候选、写入及全量回读。
- `一键恢复原系统.cmd`：使用本设备原备份恢复 system。
- `校验刷写包.cmd`：仅核对电脑文件，不枚举或连接设备。
- `data/system.delta`：支持底包上的差分数据；电脑端重建完整 1 GiB 镜像，设备端始终整分区写入。
- `runtime`：官方 Python Windows x64 便携运行时及原许可证。
- `source`、`licenses`：项目、修改依赖及固定第三方源码/通知。原始通知中的历史开发边界保留；它们不代表本包完成公开发布或原厂授权。

原系统和候选的完整 SHA-256、每个包成员的大小与 SHA-256 在 `package-manifest.json`。包不携带开发笔 userdata、NV 或完整原厂系统镜像，也没有额外字体。

页面退出会回收播放会话、播放器与页面相关资源；独立本地服务用于响应下次打开，不能把“退出页面”解释为后台占用绝对为零。实际播放、退出资源和长时间运行仍需本包实机验收。
